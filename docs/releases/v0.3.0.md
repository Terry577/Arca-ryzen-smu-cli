# ryzen-smu-cli v0.3.0

This feature release adds validated maximum boost-frequency limit controls.

## Highlights

- `--get-fmax` reads the current FMax limit in MHz.
- `--set-fmax <MHz>` sets the maximum boost-frequency limit for all cores.
- FMax inputs must be positive whole numbers in 25 MHz steps, such as 5225 or
  5250. Invalid values are rejected before hardware initialization.
- Read and write capability checks prevent unsupported SMU commands from being
  issued.
- Rejected writes and invalid zero-value reads return nonzero exit codes and
  are never reported as success.
- The read-only hardware smoke test now covers FMax.

## Usage

Read the current maximum boost-frequency limit:

```powershell
.\ryzen-smu-cli.exe --get-fmax
```

Set a new limit and read it back:

```powershell
.\ryzen-smu-cli.exe --set-fmax 5250 --get-fmax
```

FMax changes can destabilize a system when the requested limit exceeds what
the CPU, cooling, voltage configuration, or firmware can sustain. Firmware is
the final authority and may reject a syntactically valid value. Make small
changes and validate them under load.

## Validation

This release passed 66 automated tests. The read and write paths were also
validated on an AMD Ryzen 7 9800X3D with PawnIO 2.2.0: FMax was read as
5225 MHz, written back unchanged at 5225 MHz, and read again successfully.
