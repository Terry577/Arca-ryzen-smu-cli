# ryzen-smu-cli v0.3.5

This compatibility release makes the compact Curve Optimizer index the formal
contract for readable and writable cores. Physical fuse topology remains
available for downcore diagnostics, but no longer prevents an otherwise valid
per-core offset read or write.

## Compact operable-core contract

`--get-offsets-terse` now discovers a compact `0..N-1` map from the SMU
selectors that answer the current per-core offset probe. Candidate
selectors are explicitly sorted before compact keys are assigned. The Nth CSV
item and compact key N used by `--offset` therefore resolve to the same
selector.

The mapper no longer requires:

- a complete factory core-disable map;
- an exact eight-physical-slots-per-reported-CCD topology;
- a topology-derived enabled-core count that matches the readable offset
  count; or
- platform qualification intended for physical-slot operations.

Those checks were unrelated to the operation requested and could reject
systems whose offset selectors worked normally. They remain in force for
`--disable-cores`, `--enable-all-cores`, and `--get-physical-cores`, where
physical topology is the object being inspected or changed.

The relaxed dependency is not a relaxed SMU result check. A failed selector
read, or a success payload outside the signed `-50..50` hardware range, is
never counted as a core. A qualified topology-derived enabled-core count is a
soft performance hint: a matching healthy invocation probes every candidate
once and caches the successful values for terse output. If the count differs
or is unqualified, only failed selectors are retried, allowing a transient
busy response to join the original map without repeating healthy reads. Every
failed selector receives up to three focused attempts before a persistently
smaller successful set is accepted instead of restoring the old hard gate. An
all-failed range likewise receives up to three attempts and then returns a
nonzero mapping failure. This keeps the normal call count below the previous
probe-plus-second-read implementation.

## Single CCD, dual CCD, and disabled CCDs

The enabled-CCD bitmap is used as an optional discovery hint. If CCD0 is
entirely disabled and CCD1 survives, the compact map starts at key 0 while its
internal address retains the real CCD1 selector.

When the bitmap is missing on dual-CCD-capable Raphael/Dragon Range or Granite
Ridge/Fire Range silicon, both possible CCD selectors are probed in ascending
order. An invalid or disabled selector is discarded unless it successfully
answers the SMU read command. Missing or partial per-core fuse masks are
likewise no longer fatal.

A nonzero single-CCD bitmap remains the zero-overhead primary fast path. If
every selector in that range fails, version 0.3.5 treats the bitmap as possibly
stale and probes the opposite CCD selector. A healthy primary range therefore
still costs exactly one read per candidate, while a surviving CCD behind stale
metadata can still be discovered.

APU offset reads preserve the full compact selector index for indices above
seven instead of aliasing them to a lower index. This extended APU mapping is
structurally implemented but has not yet been qualified on representative real
hardware. Firmware still determines whether any candidate selector is
supported, and every write remains guarded by immediate exact read-back; a
rejection, read failure, or mismatch exits with code 6 and is never printed as
success. That value check does not by itself qualify physical target identity
above APU index 7.

## Verified writes

`--offset` retains its `-50` through `50` input range and firmware remains the
final authority. After the SMU accepts a write, version 0.3.5 immediately reads
the same mapped selector:

- a rejected write returns exit code 6;
- a failed read-back returns exit code 6;
- a mismatched value returns exit code 6; and
- success is printed only after an exact match.

Keyed assignments are executed in ascending compact-key order so positional
and keyed forms have one deterministic mapping and mutation order. When a
single invocation combines `--offset` with `--get-offsets-terse`, each
verified read-back updates the cached map before the CSV is printed; the
combined command never emits the pre-write value.

## Vcore stream cadence

This release also includes the pending stream scheduler correction. If a
hardware read overruns one or more requested intervals, `--stream-vcore` skips
expired cadence points and waits for the next future point. It no longer emits
an immediate catch-up sample with a duplicate monotonic millisecond timestamp.

## Validation

The Release test suite covers:

- stale topology-derived enabled-core counts;
- incomplete and unqualified factory topology;
- single- and dual-CCD compact maps;
- a surviving CCD1 after whole-CCD disable;
- missing CCD bitmap fallback on desktop-die Zen 4 and Zen 5;
- stale nonzero CCD bitmap fallback without extra healthy-path reads;
- exclusion of every failed selector read;
- exclusion of out-of-range SMU success payloads;
- one probe per candidate on the healthy terse-output path;
- third-pass focused recovery of one transiently failed selector without
  rereading the healthy selectors;
- acceptance of a persistently smaller response set despite a stale soft
  topology hint;
- deterministic compact-key write order;
- post-write cache refresh for combined write-plus-terse commands;
- immediate read-back success and mismatch; and
- monotonic Vcore stream scheduling after a slow read.

Before public release, run the read-only smoke test on representative single-
and dual-CCD hardware. On any system with a disabled CCD, compare two
consecutive `--get-offsets-terse` runs and verify that their item count and
ordering are stable before attempting a write. Pass
`-IncludePhysicalTopology` only when separately validating factory-slot
diagnostics; those stricter diagnostics are no longer a prerequisite for the
compact offset smoke path.
