# ryzen-smu-cli v0.3.2

This feature release adds explicit, machine-readable CPU-rail Vcore telemetry
for CurveAlign and other automation.

## Highlights

- `--get-vcore` emits one invariant-format Vcore sample.
- `--stream-vcore --interval-ms 150` keeps a single PawnIO/SMU session open
  and emits timestamped samples without repeated hardware initialization.
- `--info` now reports PM-table version, PM-table size, and the selected Vcore
  source/index for field diagnostics.
- Vcore mapping is an exact PM-table-version whitelist. Unknown layouts return
  exit code 3 instead of guessing or substituting per-core VID.
- Read failures and implausible values return exit code 6, write diagnostics
  only to stderr, and never emit a fake sample.

## Usage

Read one sample:

```powershell
.\ryzen-smu-cli.exe --get-vcore
```

Example stdout:

```text
Current Vcore: 1.225000 V.
```

Start a persistent 150 ms stream:

```powershell
.\ryzen-smu-cli.exe --stream-vcore --interval-ms 150
```

Each stdout record is a flushed, headerless TSV line:

```text
VCORE	0	7	2026-07-31T08:30:00.1234567+00:00	1.225000
```

The fields are record type, sequence, monotonic elapsed milliseconds, UTC
timestamp, and volts. Stop the stream with Ctrl+C.

Ctrl+C and a closed stdout pipe both unwind through controller disposal. The
global PCI-access mutex is held only for an individual PM-table refresh, not
for the lifetime of the stream.

## Supported PM-table layouts

| Version | Source |
| --- | --- |
| `0x00540004` | Zen 4 VDDCR, entry 47 |
| `0x00540104` | Zen 4 Vcore Peak, entry 18 |
| `0x00620105` | Granite Ridge Vcore Peak, entry 18 |
| `0x00620205` | Granite Ridge two-CCD Vcore Peak, entry 18 |

The Granite Ridge mapping uses the shared leading telemetry block; no
per-core or per-CCD array index is inferred. Other Zen 4/Zen 5 table versions,
including `0x00540208`, `0x00621102`, and `0x00621202`, remain unsupported
until their Vcore field is verified.

## Validation status

The release preparation passes the complete automated Release build and test
suite. The following hardware checks are still required before publishing:

- compare `0x00540104` entry 18 with Ryzen Master or HWiNFO CPU-rail
  telemetry on a representative Zen 4 processor under idle and controlled
  load;
- compare `0x00620105` entry 18 with HWiNFO CPU-rail/SVI telemetry on a
  one-CCD Granite Ridge processor under idle and controlled load;
- repeat that comparison for `0x00620205` on a two-CCD Granite Ridge
  processor;
- verify the stream remains close to the requested 150 ms cadence and does
  not contend with Curve Optimizer/FMax commands;
- capture `--info` from unsupported Zen 4 mobile and desktop layouts before
  adding any new mapping.

No release tag or package should be treated as hardware-validated until those
checks pass.
