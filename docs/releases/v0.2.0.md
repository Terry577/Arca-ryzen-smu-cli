# ryzen-smu-cli v0.2.0

This is the first maintained release of the Arca fork and a major reliability
and safety update over 0.1.3.

## Highlights

- ZenStates-Core updated from v1.75 to v1.90 with PawnIO-based SMU access and
  newer Zen 5 support.
- Missing native assets and the broken publish pipeline are fixed.
- Hardware initialization is lazy: `--help`, `--version`, and parse errors no
  longer require administrator privileges.
- Every SMU and AMD ACPI result is checked before success is reported.
- Typed validation and meaningful process exit codes make automation reliable.
- Topologies beyond two CCDs are supported.
- Zen and Zen 2 CCD/CCX addressing is corrected.
- Requests that would disable every physical core are refused.
- 49 automated tests plus a real read-only Ryzen 7 9800X3D smoke test pass.

- `checksums-sha256.txt`
  - SHA-256 hashes for all archives.

Keep `inpoutx64.dll` beside `ryzen-smu-cli.exe`. Run hardware commands from an
Administrator PowerShell.

## Important behavior changes

- `--get-offsets-terse` now prints one CSV line and no heading.
- `--offset` uses enabled-core indices.
- `--disable-cores` uses physical core-slot indices.
- Failed commands now return nonzero exit codes.
- Curve Optimizer input accepts `-50` through `50`, but firmware may reject
  values unsupported by a particular CPU.

Use `--get-enabled-cores` before making changes if the system has fused or
manually disabled cores.

## Safety

SMU and Curve Optimizer writes can destabilize the system. Core-disable
changes require a reboot. Keep a known-good BIOS profile and validate changes
gradually.

InpOutx64 is an unsupported legacy native component. The official v1.5.0.1
distribution DLL is included byte-for-byte and pinned by SHA-256. Verify the
release checksums before running the executable.
